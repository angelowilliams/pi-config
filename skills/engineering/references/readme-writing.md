# README writing

- Always start with a brief 1-2 sentence overview of what the repo is for.
- Prioritize what a reader needs to do to start using the project.
- Separate prerequisites (what must be available) from setup (what to do).
- Give each section a clear purpose; avoid repeating information across sections.
- Use plain language, short explanations, and lists when they improve scanning.
- Keep the README focused; move detailed implementation, troubleshooting, and verification material elsewhere when it isn't needed for the main workflow.
